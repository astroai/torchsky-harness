Torchsky's scientific evaluation lived beside its implementations, with private benchmark imports in package tests and runners that could silently select the current checkout. This extraction gives existing WCS, sphere, map/SMACS, and catalog evaluation its own repository and installed `torchsky_harness` namespace.

The CLI records the actual installed subject, content/artifact hashes, execution state and logs. Native kernels and bounded library tests remain in torchsky; reference adapters, existing acceptance files, evaluation tests, acquisition/CANFAR runners and compact campaign history move here. No PSF, detection, segmentation or SSL placeholders are introduced. Frozen CANFAR jobs and data locations are unchanged.

Validation: both repositories passed Ruff/compile preflight; focused migrated and retained tests passed, with optional comparator skips reported in docs/extraction-status.md; test collection found no import errors. Independently installed subject/harness wheels executed small WCS, map, catalog and native sphere probes from an unrelated directory. The lean-profile healpy probe correctly failed for its missing required comparator; large, GPU and full acceptance suites were not run.

The subject wheel includes the pre-existing local torchsky development state, identified by SHA256 in docs/source-snapshot.json; those library changes are not published in this extraction. Torchsky's companion edits remain in its working tree. Scientific workflows require a private-repository SUBJECT_READ_TOKEN and an exact subject revision, and are manual during the transition. Existing torchfits-owned I/O evidence is retained with explicit ownership rather than dropped. Historical report bytes are preserved, including their original formatting and unavailable metrics.
